# ตรวจคุณภาพและทดสอบแอป

KODRA มีเครื่องมือตรวจว่าแอปใช้งานได้จริงก่อนเผยแพร่ ส่วนใหญ่อยู่ในแท็บ **ฟีเจอร์**, **เทสต์**
และ **เผยแพร่** ของแผง Preview

## รายการฟีเจอร์ (แท็บ ฟีเจอร์)

รายการสิ่งที่แอปต้องทำได้ มาจากแบบร่างแอป (App Blueprint) จาก AI หรือที่คุณเพิ่มเอง
แต่ละรายการแสดงสถานะ **ใช้ได้**, **ใช้ไม่ได้**, **ยังไม่ได้ทดสอบ** หรือ **ต้องตรวจเอง**

- **ตรวจทั้งหมด** — รันชุดทดสอบที่ผูกกับแต่ละฟีเจอร์
- **ให้ AI แก้** (ฟีเจอร์ที่ใช้ไม่ได้) / **ให้ AI ทดสอบ** (ฟีเจอร์ที่ยังไม่ได้ทดสอบ)
- ฟีเจอร์แบบ ต้องตรวจเอง ให้ลองเองแล้วกด **ใช้ได้แล้ว** หรือ **ยังใช้ไม่ได้**

## การ์ดในแท็บ เทสต์

| การ์ด | ทำอะไร |
|---|---|
| **ตรวจกดทุกปุ่ม** | ลองกดทุกปุ่ม ลิงก์ และส่งทุกฟอร์ม (มือถือและเดสก์ท็อป) เพื่อหาปุ่มที่กดแล้วไม่ทำงานหรือฟอร์มพัง ไม่บันทึกข้อมูลจริง (คำขอที่เขียนข้อมูลถูกบล็อก ปุ่มเสี่ยงและฟอร์มชำระเงินถูกข้าม) ใช้เวลา 1–3 นาที |
| **ตรวจหน้าตาที่เปลี่ยนไป** | เทียบหน้าตาแอปกับ "ต้นแบบ" ที่คุณอนุมัติไว้ แสดงภาพ ก่อน/หลัง และจุดที่ต่าง |
| **ตรวจระบบเข้าสู่ระบบ** | ตรวจว่าหน้าที่ต้องล็อกอินเปิดไม่ได้ถ้ายังไม่เข้าสู่ระบบ และสมัคร/เข้า/ออกจากระบบได้ ใช้บัญชีทดสอบชั่วคราวเท่านั้น |
| **API ของแอป** | เรียกทุก route ฝั่งเซิร์ฟเวอร์แบบไม่ล็อกอิน หา route ที่พัง (5xx) หรือส่งข้อมูลส่วนตัวออกไป |

ทุกการ์ดมีปุ่ม **ให้ AI แก้** เมื่อพบปัญหา (ต้องเปิดแชตไว้)

### บันทึกต้นแบบหน้าตา (visual baseline)

- กด **บันทึกเป็นต้นแบบ** ในการ์ด ตรวจหน้าตาที่เปลี่ยนไป เพื่อเก็บหน้าตาปัจจุบัน หรือ
- **ติดดาว** เวอร์ชันที่พอใจใน Version History — ถ้าพรีวิวไม่ได้แสดงเวอร์ชันนั้นอยู่ จะขึ้นข้อความ
  "ติดดาวแล้ว ระบบจะบันทึกหน้าตาต้นแบบเมื่อ preview แสดงเวอร์ชันนี้" แล้วระบบจะถ่ายเมื่อพรีวิว
  เปิดเวอร์ชันนั้นครั้งถัดไป

จากนั้นกด **เปรียบเทียบ** เมื่อต้องการตรวจ ถ้าการเปลี่ยนแปลงตั้งใจ กด **ยอมรับทั้งหมดเป็นต้นแบบใหม่**

## ทดสอบแอปแบบผู้ใช้จริง (การ์ด ทดสอบแอป)

ในโหมด Agent หลังสร้างหรือแก้หลายหน้า AI อาจเปิดแอปแล้วลองใช้ตามเป้าหมายจากคำขอของคุณ
(เช่น สมัคร → เพิ่มสินค้า → ชำระเงิน) หรือสั่งเองได้ เช่น *"ทดสอบแอปแบบผู้ใช้จริง"*
ในแชตจะมีการ์ด **ทดสอบแอป** บอกผลผ่าน/ไม่ผ่านของแต่ละเป้าหมาย กด **ดูรีเพลย์** เพื่อดู
**ภาพทีละขั้น** หรือ **วิดีโอ** (เปิดที่จุดแรกที่ล้มเหลว) ขั้นตอนเสี่ยงและการชำระเงินจะถูกบล็อก
ผลเก็บในโฟลเดอร์ `.dyad/test-runs/` ของแอป (10 ครั้งล่าสุด)

## คะแนนคุณภาพ (แผง เผยแพร่)

การ์ด **คะแนนคุณภาพ** กด **เริ่มตรวจ** ระบบจะ build เวอร์ชันจริงแล้ววัด **การเข้าถึง**
(WCAG 2.2 AA) และ **ความเร็ว** บน มือถือ และ คอม (คะแนนเต็ม 100) ใช้เวลาไม่กี่นาที
มีสวิตช์ห้ามเผยแพร่ถ้ามีปัญหาการเข้าถึงระดับวิกฤตหรือร้ายแรง (เปิดไว้เป็นค่าเริ่มต้น)

## ตรวจก่อนเผยแพร่ (พร้อมเผยแพร่หรือยัง)

ในแท็บ **เผยแพร่** การ์ด **พร้อมเผยแพร่หรือยัง** มีการตรวจสองระดับ:

- **ตรวจด่วน** (ไม่กี่วินาที) — รันเมื่อเปิดแผง เมื่อกด **ตรวจอีกครั้ง** และก่อนเผยแพร่ ตรวจ error ในโค้ด
  error ในพรีวิว ฟีเจอร์ที่จำเป็น และพื้นฐานของหน้าเว็บ (ชื่อหน้า favicon หน้า 404 ฯลฯ)
  ส่วนรายการที่ช้าจะใช้ผลจากการตรวจแบบเต็มครั้งล่าสุด และบอกว่าตรวจไว้เมื่อไร
- **ตรวจแบบเต็ม** (ประมาณ 3–5 นาที) — กด **ตรวจแบบเต็ม (ประมาณ 3–5 นาที)** จะ build เวอร์ชันจริง
  รันชุดทดสอบที่บันทึกไว้ ไล่เปิดทุกหน้า รัน unit test และ lint ของแอป ตรวจกดทุกปุ่ม เทียบหน้าตา
  ตรวจ API และระบบเข้าสู่ระบบ

ตอนกด **เผยแพร่** ครั้งแรก ถ้าไม่มีการตรวจแบบเต็มใน 24 ชั่วโมงล่าสุด (หรือโค้ดเปลี่ยนไปเกิน 5 ไฟล์)
จะถาม "ตรวจแบบเต็มก่อนเผยแพร่ไหม?" เลือก **เผยแพร่ด้วยผลตรวจด่วน** หรือตรวจแบบเต็มก็ได้

ถ้าพบปัญหาจะขึ้น "พบปัญหา N รายการ แก้ก่อนได้ หรือจะเผยแพร่เลยก็ได้" — กด **ให้ AI แก้ทั้งหมด**
หรือ **เผยแพร่เลย** (ไม่บังคับ) ส่วนการตรวจความปลอดภัยเป็นอีกขั้นที่แยกกัน

รายการที่ฟีเจอร์ใหม่เพิ่มเข้ามา:

| รายการ | ระดับ |
|---|---|
| ฟีเจอร์ที่จำเป็นใช้งานได้จริง | ตรวจด่วน + เต็ม |
| สีและสไตล์เป็นไปตามโทเคนของแบรนด์ | ตรวจด่วน (เตือนเท่านั้น) |
| หน้าที่ต้องล็อกอินเปิดไม่ได้ถ้ายังไม่เข้าสู่ระบบ | ตรวจด่วน (ถ้าพรีวิวเปิดอยู่) + เต็ม |
| ไม่มีปุ่มที่กดแล้วไม่ทำงานหรือฟอร์มที่ใช้ไม่ได้ | เต็ม (เตือน) |
| ทุกคนใช้งานได้ (การเข้าถึง) / โหลดเร็วบนมือถือ | เต็ม |
| Unit test ผ่านทั้งหมด / ไม่มีข้อผิดพลาดจาก lint | เต็ม |
| API ตอบกลับได้และปกป้องข้อมูลส่วนตัว | เต็ม (เตือน) |
| หน้าตายังเหมือนเวอร์ชันที่อนุมัติไว้ | เต็ม (เตือน, ข้ามถ้ายังไม่มีต้นแบบ) |

## English

- **Features** tab: required features with **Works / Not working / Not tested
  yet / Check by hand**; **Verify all**, **Ask AI to fix**.
- **Tests** tab cards: **Click-everything check** (clicks every button and
  submits every form; writes are blocked), **Visual regression** (**Save as
  baseline** / **Compare**; starring a version queues a baseline that is captured
  when the preview runs that version), **Sign-in check** (throwaway test
  accounts), **API routes** (calls server routes signed out).
- **App Test** chat card: the agent uses the app like a user and records a
  **Replay** (frames/video); runs are saved in `.dyad/test-runs/`.
- **Quality scores** (Publish panel): accessibility and mobile/desktop
  performance on a production build.
- **Ready to publish?**: a quick check (seconds) runs on open and before
  publishing and reuses slow results from the last full check; **Run full check
  (≈3–5 min)** builds, replays flows, crawls, and runs unit tests, lint and the
  new checks. Publishing asks to run the full check when the last one is older
  than 24 h or more than 5 files changed. Failures are a soft block: "N problems
  found. Fix them, or publish anyway." (**Fix everything with AI** / **Publish
  anyway**). The security check is a separate gate.
