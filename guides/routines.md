# งานตามกำหนดเวลา (Routines)

**งานตามกำหนดเวลา** คืองานดูแลแอปที่ KODRA ทำเบื้องหลังตามเวลาที่ตั้งไว้ แล้วเก็บผลไว้ให้คุณตรวจ
เช่น ตรวจสุขภาพแอปทุกเช้า หรืออัปเดตแพ็กเกจทุกสัปดาห์ งานเหล่านี้ **ไม่แตะบรานช์หลักของคุณเลย**
และไม่เปลี่ยนเว็บที่เผยแพร่อยู่

ตั้งได้ที่แท็บ **Configure** (ตั้งค่า) ในแผง Preview ของแอป → การ์ด **งานตามกำหนดเวลา** → **เพิ่มงาน**

## รูปแบบงาน

| รูปแบบงาน | ทำอะไร | แก้โค้ดไหม |
|---|---|---|
| **ตรวจสุขภาพแอป** (Health check) | รันการตรวจก่อนเผยแพร่แบบเต็ม (เหมือนปุ่ม **ตรวจแบบเต็ม** ใน [พร้อมเผยแพร่หรือยัง](quality-checks.md)) แล้วรายงานสิ่งที่แย่ลงจากรอบก่อน | ไม่แก้อะไรในแอป |
| **อัปเดตแพ็กเกจ** (Dependency updates) | อัปเดตเวอร์ชันย่อย (minor/patch) บนบรานช์แยก รันตรวจชนิดข้อมูล บิลด์ และยูนิตเทสต์ แล้วเก็บบรานช์ไว้ให้ตรวจ | เฉพาะบนบรานช์ `kodra/routines/deps-…` |
| **กำหนดเอง** (Custom) | ให้เอเจนต์ทำตาม **พรอมต์** ของคุณ | ขึ้นกับ **วิธีทำงาน** (ดูด้านล่าง) |

### อัปเดตแพ็กเกจ

- อัปเดตเฉพาะ minor/patch ภายในช่วงเวอร์ชันที่แอปกำหนดไว้ ส่วนแพ็กเกจที่มีเวอร์ชันหลัก (major) ใหม่
  จะแค่แสดงรายการ ไม่อัปเดตให้
- ทำงานในสำเนาแยก (git worktree) บนบรานช์ชื่อแบบ `kodra/routines/deps-2026-11-23-r4`
  พรีวิวและโค้ดที่คุณเปิดอยู่จึงไม่ถูกแตะ
- ติ๊ก **เปิด Pull Request บน GitHub ให้ตรวจ** ได้ถ้าแอปเชื่อม [GitHub](../integrations/github.md) ไว้
  (ถ้ายังไม่เชื่อม บรานช์ก็ยังเก็บไว้ให้ตรวจ)
- **ไม่มีการรวม (merge) เข้าบรานช์หลักโดยอัตโนมัติ** ไม่ว่ากรณีใด — คุณตัดสินใจเองหลังตรวจ

### กำหนดเอง: วิธีทำงาน

| วิธีทำงาน | ผล |
|---|---|
| **ถาม (อ่านอย่างเดียว)** / **วางแผน (อ่านอย่างเดียว)** | เอเจนต์อ่านโค้ดแล้วตอบหรือวางแผน ไม่แก้ไฟล์ เหมาะกับงานอย่าง "ตรวจโค้ดหาช่องโหว่ แล้วสรุปสิ่งที่ควรแก้" |
| **เอเจนต์บนบรานช์แยก** | เอเจนต์แก้โค้ดได้ แต่บนบรานช์ `kodra/routines/custom-…` เท่านั้น (เปิด Pull Request ได้เหมือนอัปเดตแพ็กเกจ) |

ข้อควรรู้ของ **เอเจนต์บนบรานช์แยก**:

- ระหว่างที่งานรัน แอปจะสลับไปอยู่บนบรานช์ของงาน **พรีวิวจึงแสดงโค้ดของบรานช์นั้น** และแชตอื่น
  ของแอปนี้จะส่งข้อความไม่ได้จนกว่างานจะเสร็จ เมื่อเสร็จแล้วแอปจะสลับกลับบรานช์เดิมของคุณ
- **ไม่เริ่มงานถ้าแอปมีการเปลี่ยนแปลงที่ยังไม่ได้บันทึก (uncommitted)** — กันไม่ให้งานของคุณติดไปอยู่
  บนบรานช์ของงาน ให้บันทึก (commit) หรือยกเลิกการเปลี่ยนแปลงก่อน
- ถ้าเอเจนต์ไม่ได้แก้อะไร บรานช์ว่างจะถูกลบทิ้ง

## ตั้งเวลา

- **ความถี่**: **ทุกวัน** หรือ **ทุกสัปดาห์** (เลือก **วัน**) พร้อม **เวลา** และ **เขตเวลา**
  (ค่าเริ่มต้นเป็นเขตเวลาของเบราว์เซอร์/เครื่องคุณ)
- **พลาดรอบ** (เช่น ปิดเครื่องหรือปิด KODRA ไว้) — เมื่อเปิดครั้งถัดไป งานจะรัน **ครั้งเดียว**
  แทนทุกรอบที่พลาด ไม่รันซ้ำหลายรอบ
- **กำลังแชตอยู่** — ถ้าถึงเวลาแล้วแอปกำลังทำงานกับแชต งานจะรอได้ **ไม่เกิน 1 ชั่วโมง**
  ถ้ายังไม่ว่างจะ **ข้าม** รอบนั้นพร้อมบอกเหตุผล
- รันได้ทีละงานต่อแอป กด **รันตอนนี้** เพื่อรันทันที (ใช้ไม่ได้ถ้าแอปกำลังทำงานกับแชตอยู่) หรือ **หยุด**
  เพื่อยกเลิกงานที่กำลังรัน ปิดสวิตช์เพื่อ **หยุดชั่วคราว**
- แต่ละรอบมีเวลาจำกัด (ตรวจสุขภาพแอป 20 นาที อื่น ๆ 30 นาที) เกินกว่านั้นจะขึ้นสถานะ **หมดเวลา**

## ค่าใช้จ่าย

- **วงเงินสูงสุดต่อรอบ (USD)** — แต่ละรอบจะหยุดเมื่อใช้ถึงวงเงินนี้ (เว้นว่าง = ไม่จำกัด)
- งานจะ **ไม่เริ่ม** ถ้าใช้ถึง **ขีดจำกัดค่าใช้จ่ายรายวันหรือรายเดือน** แล้ว
  ("ไม่ได้เริ่ม เพราะใช้ถึงวงเงินรายวันแล้ว" / "…รายเดือนแล้ว") ดู
  [ค่าใช้จ่าย AI](spend-and-routing.md)

## ดูผลลัพธ์

- ผลของแต่ละรอบอยู่ใน **แชตใหม่** ชื่อ **"Scheduled: <ชื่องาน> — <วันที่>"** กด **เปิดแชท** จากการ์ดงาน
- สถานะ: **ผ่าน**, **ไม่ผ่าน**, **รอตรวจ**, **ข้าม**, **หมดเวลา**, **ยกเลิกแล้ว**
- เมื่องานเสร็จจะมีการแจ้งเตือน (บน desktop มีการแจ้งเตือนของระบบปฏิบัติการด้วย)
- ถ้ามีผลที่ต้องให้คุณตัดสินใจ (เช่น บรานช์อัปเดตแพ็กเกจ) จะขึ้นแถบ
  **"มีผลงานตามกำหนดเวลารอให้คุณตรวจ (N)"** กด **ดู Pull Request** หรือเปิดแชต แล้วกด **ตรวจแล้ว**

## Desktop และเวอร์ชันเว็บ

- **Desktop:** งานรันเมื่อ KODRA เปิดอยู่ ถ้าปิดไว้ตอนถึงเวลา จะรันครั้งเดียวเมื่อเปิดครั้งถัดไป
- **เวอร์ชันเว็บ:** งานรัน **แม้คุณออกจากระบบหรือปิดเบราว์เซอร์** — เซิร์ฟเวอร์จะปลุก workspace ของคุณ
  เมื่อถึงเวลา ยกเว้นบัญชีที่ถูกระงับ หรือพื้นที่เก็บข้อมูลเต็ม

## English

**Routines** are scheduled maintenance jobs for an app: the app's **Configure**
tab → **Routines** → **Add routine**. They never touch your main branch or your
live site.

- **Templates:** **Health check** (runs the full pre-publish check and reports
  what got worse; changes nothing), **Dependency updates** (minor/patch only, on
  a `kodra/routines/deps-…` branch in a separate worktree; type check, build and
  unit tests; optional GitHub pull request; **never merged automatically**;
  new majors are only listed) and **Custom** (your prompt, run as **Ask
  (read-only)**, **Plan (read-only)** or **Agent on a separate branch**).
- **Agent on a separate branch:** while it runs the app is checked out on the
  routine branch, so the preview shows that branch and other chats in the app
  can't send; it refuses to start when the app has uncommitted changes.
- **Schedule:** **Every day** / **Every week** at a time in a **Time zone**.
  Missed runs (KODRA closed) run **once** at the next start. If you're chatting
  when a run is due it waits up to an hour, then is skipped. **Run now**,
  **Stop**, and a pause switch; runs time out after 20 min (health check) or
  30 min.
- **Spending:** **Spend cap per run (USD)**; routines don't start once your daily
  or monthly spend limit is reached.
- **Results:** a new chat titled **"Scheduled: <name> — <date>"**, a
  notification, and a **"Routine results need your review"** banner with
  **View pull request** / **Mark as reviewed**.
- **Web version:** routines run even when you're signed out — the server wakes
  your workspace — except for suspended accounts or when storage is full.
